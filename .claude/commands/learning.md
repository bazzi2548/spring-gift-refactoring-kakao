리팩토링 검수 후 학습 내용을 LEARNING.md에 기록한다.

## 기록 대상

$ARGUMENTS

대상이 지정되지 않은 경우, `git diff`로 최근 변경사항을 분석하여 학습 주제를 파악한다.

## 실행 절차

### 1단계: 변경사항 파악
아래 명령어를 병렬로 실행하여 리팩토링 내용을 파악한다:
- `git diff` — 현재 변경 내용
- `git diff --cached` — staged 변경 내용
- `git log --oneline -5` — 최근 커밋 히스토리

변경된 파일을 읽고 리팩토링의 핵심 주제를 식별한다.

### 2단계: LEARNING.md 현재 내용 확인
LEARNING.md를 읽어 기존 목차와 섹션 번호를 파악한다.
마지막 섹션 번호 다음 번호로 새 항목을 추가한다.

### 3단계: 학습 내용 작성
아래 템플릿에 따라 학습 내용을 작성한다:

```markdown
## N. {제목}

### 키워드
- 관련 기술 키워드를 나열한다 (예: `@Embeddable`, `BCryptPasswordEncoder`, `HandlerMethodArgumentResolver`)

### 구현 원리
- 해당 기술/패턴이 어떻게 동작하는지 설명한다.
- "왜 이 방식을 선택했는가"를 포함한다.
- 대안이 있었다면 대안과 비교한다.

### 구현 코드
- 핵심 코드를 Before/After로 보여준다.
- 전체 코드가 아닌 변경의 핵심만 발췌한다.

```java
// Before
기존 코드

// After
변경된 코드
```

### 장단점
**장점:**
- 구체적인 장점

**단점 또는 트레이드오프:**
- 구체적인 단점이나 주의할 점

### 기대효과
- 이 변경이 프로젝트에 미치는 실질적인 효과를 기술한다.
```

### 4단계: 사용자 확인
작성한 내용을 사용자에게 보여주고 승인을 받은 뒤 LEARNING.md에 추가한다.

## 작성 원칙
- 한국어로 작성한다.
- 추상적인 설명보다 이 프로젝트에서 실제로 적용한 내용을 기준으로 쓴다.
- 코드 예시는 프로젝트의 실제 코드에서 발췌한다.
- 이미 LEARNING.md에 있는 내용과 중복되지 않도록 한다. 기존 항목과 겹치면 기존 항목을 보강한다.
